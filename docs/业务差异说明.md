# 业务差异说明 · 云宿 SaaS vs 焊工考试管理系统

> 对应交付物：业务差异文档（对标焊工考试系统 PRD：新增住宿业务域、公安实名合规、多端预订闭环）。
> 目的：说明哪些能力继承自参考系统、哪些为住宿行业新增、哪些需替换，便于后续维护者理解架构来源。

---

## 1. 参考系统能力基线

参考系统（焊工考试管理系统）为“公众号 + 小程序 + H5 + PC 后台 + 独立 App”的考试培训类 SaaS，具备：

- 多端账号体系与 UnionID 互通
- 平台/租户两级 RBAC、审计日志
- 多语言 i18n、菜单可视化、系统参数可视化
- 多驱动对象存储（本地/S3/OSS/COS/MinIO）
- 富文本编辑、图片/附件上传
- 微信支付、模板消息/订阅消息
- 题库/考试/证书/培训等考试业务域

本项目**继承其技术底座与多端形态**，将业务域替换为住宿运营，并新增住宿行业特有的实时房态、前台接待、公安实名与财务结算。

---

## 2. 能力对照

| 能力 | 参考系统 | 云宿 SaaS | 差异说明 |
|---|---|---|---|
| 多租户 | 有 | 有（共享库行级隔离） | 住宿业务表全部含 `tenant_id`，平台表白名单 |
| 两级 RBAC | 有 | 有 | 平台超管 + 租户六角色；模块级拦截 |
| 审计 | 有 | 有 | 写操作/失败/403/跨租户访问 |
| UnionID | 有 | 预留（demo openId） | 需微信开放平台资质后接真实 `code2Session` |
| 对象存储 | 5 驱动 | 本地 + MinIO 已实现 | OSS/COS/S3 可通过兼容层/后续适配 |
| i18n | 有 | 词条级已实现 | 业务内容（房型/门店）多语言字段待扩展 |
| 菜单可视化 | 有 | 后台配置 + H5 读取 | 小程序/管理端本地配置，未全端热更新 |
| 富文本 | WangEditor | **未实现** | 当前配置页使用普通输入/文本域；房型介绍为纯文本 |
| 上传组件 | 拖拽/多图/进度 | 基础上传接口 + 页面 | 未做拖拽排序/进度条/多图组件封装 |
| 微信支付 | 有 | 记账占位 | 需商户号、证书、回调、对账 |
| 模板/订阅消息 | 有 | 模板配置 + 站内消息 | 真实下发待联调 |
| 短信 | 预留 | 字段/模板预留 | 未接服务商 |
| 独立 App | 有 | Flutter 骨架 | 未编译/真机验证 |
| 公众号运营 | 有 | 配置页预留 | 未实现素材/粉丝/群发/菜单同步 |

## 3. 住宿行业新增业务域

### 3.1 主数据

| 模块 | 新增内容 | 关键表 |
|---|---|---|
| 门店/楼栋 | 多门店、楼栋楼层 | `biz_store`、`biz_building` |
| 房型 | 面积/可住人数/床型/设施/图片/基准价 | `biz_room_type` |
| 房间 | 房号/楼层/房型/实时房态 | `biz_room` |
| 房价日历 | 房型×日期×价格类型（门市/渠道/协议） | `biz_rate`、`biz_rate_log` |
| 房态日志 | 空房/预订/在住/脏房/维修/关闭 | `biz_room_status_log` |

> 考试系统无“物理房间”和“日期库存”概念；住宿系统必须处理**时间维度库存**与**房态并发**。

### 3.2 预订与订单

- 来源：散客/团队/协议/OTA/候补/在线；
- 支付方式：在线支付/到店付；
- 状态机：`PENDING → CONFIRMED → CHECKED_IN → CHECKED_OUT`，可 `CANCELLED`；
- 可用房校验：按日期区间与房型统计，排除冲突订单；
- 订单号：租户内唯一，Redis 自增 + 数据库唯一键；
- 防重：`X-Request-Id`。

### 3.3 前台接待与实名

- 入住登记：住客、证件、押金、房卡、未成年人信息；
- 公安报送：`biz_police_report` 记录状态/时间/响应（当前模拟）；
- 续住、换房、提前退、延时退：`biz_stay_change` + 房态联动；
- 团队/包栋：数据模型支持多房间订单（`room_count`），页面未做专用批量办理向导。

### 3.4 房务

- 清扫任务：退房清扫/在住续扫/空房保养；
- 脏房→净房上报；
- 报修工单：报障→派工→维修→验收；
- 布草：领用/送洗/归还；
- 客诉登记/处理。

> 考试系统无“房态/保洁”实时协作；住宿系统需支持移动端一线员工快速操作。

### 3.5 财务

- 结算单：房费/押金抵扣/优惠/其他费用；
- 收银流水；
- 押金收取/退还（部分/全额）；
- 挂账（AR）与核销；
- 交接班；
- 报表：营收、入住率、ADR、RevPAR、渠道/房型/门店。

> 考试系统以订单/退款为主；住宿系统增加押金、挂账、交接班与房费按夜计算。

### 3.6 会员与营销

- 会员档案（UnionID/OpenID）、等级、积分、储值、优惠券；
- 退房自动积分/储值赠送；
- 等级按累计消费重算；
- SCRM 自动化、在线商城、裂变工具**未实现**（仅保留模型/页面入口范围）。

### 3.7 增强模块

| 模块 | 实现 | 状态 |
|---|---|---|
| OTA 渠道 | 渠道表、手动同步 | 模拟 |
| 餐饮挂账到房 | 订单/挂账接口 + 页面 | 基础实现 |
| 智能门锁 | 远程开门接口 | 模拟 |
| 身份证阅读器/自助机 | 未实现 | 预留 |
| 多门店/CRS/集团分账 | 多门店主数据 + 平台跨店统计 | 部分实现 |

## 4. 合规差异（关键）

| 合规项 | 考试系统 | 住宿系统 |
|---|---|---|
| 实名登记 | 考生实名 | 住客实名，入住强制 |
| 公安报送 | 无 | 旅馆业治安管理信息报送（当前模拟） |
| 未成年人 | 无 | 监护人信息、报告义务 |
| 特种行业 | 无 | 特种行业许可证/消防/卫生资质 |
| 隐私 | 考生信息 | 身份证号/手机号加密、掩码、最小化 |
| 数据保留 | 考试记录 | 订单/入住/结算/审计按监管要求保留 |

> 真实上线前必须取得当地公安接口规范与网络准入，完成证件加密、日志脱敏、报送失败重试与人工补报流程。

## 5. 多端差异

| 端 | 考试系统 | 云宿 SaaS |
|---|---|---|
| 小程序 | 报名/考试/证书 | 查房/预订/订单/会员 |
| 公众号 | 考试通知/菜单 | 预订入口/模板消息（预留） |
| H5 | 活动/分享 | 公开门户/房型/预订/订单查询 |
| App | 学习/考试 | 预订/订单/会员 |
| PC 后台 | 题库/考试管理 | 门店/房态/订单/前台/房务/财务/会员/报表 |
| 一线端 | 无 | 前台/保洁（复用 PC 后台按角色授权） |

## 6. 复用与替换建议

### 6.1 可直接复用

- JWT 登录、两级 RBAC、审计、租户插件
- 存储驱动抽象、AES 加密、限流/防重
- 多语言、菜单配置、参数配置
- 多端请求封装与部署方式

### 6.2 必须替换/新增

- 业务表：考试/题库/证书 → 门店/房型/房间/订单/入住/结算/房务/会员
- 业务状态机：报名/考试 → 预订/入住/退房/清扫
- 合规：考生实名 → 住客实名 + 公安报送 + 未成年人
- 财务：订单退款 → 押金/挂账/交接班/房费按夜
- 库存：考试场次 → 房型日期库存 + 房态

### 6.3 不建议照搬

- 考试类富文本/题库编辑器与住宿场景关联弱；
- 证书/成绩/培训流程不适用于住宿；
- 考试系统的“场次/座位”库存模型不能直接映射房间，需要按日期区间重新设计。

---

## 7. 结论

云宿 SaaS 在参考系统的**多端 + SaaS 底座**上，完成了住宿核心闭环（预订→入住→退房→清扫→结算→报表）与平台运营能力；当前差距主要集中在**外部生态对接**（微信真实登录/支付/消息、公安、OTA、门锁）、**富文本/上传组件体验**、**Flutter/小程序真机验证**与**生产级安全加固**。这些差距已在 README 与验收报告中显式列出，未以“已完成”口径对外表述。
