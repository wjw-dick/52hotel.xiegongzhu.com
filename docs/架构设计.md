## 1. 总体架构

```text
┌────────────────────────────── 客户端层 ──────────────────────────────┐
│  PC 管理后台(Vue3/Element Plus)   H5 门户(Vue3)   微信小程序    Flutter App │
│  ├ 平台端 /admin/                 ├ 首页/房型/预订   ├ 首页        ├ 首页       │
│  ├ 租户端（角色菜单）              ├ 订单查询        ├ 预订        ├ 预订       │
│  ├ 前台 / 保洁（同端按角色授权）     └ 会员中心        ├ 订单        ├ 订单       │
│  └ 平台下钻只读                                     └ 会员        └ 会员       │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ HTTPS / JSON / JWT Bearer
┌───────────────────────────────▼──────────────────────────────────────┐
│                        Nginx（静态资源 + 反向代理）                     │
│   /            → portal-web/dist                                      │
│   /admin/      → admin-web/dist                                       │
│   /api/        → 127.0.0.1:8080/api/                                  │
│   /uploads/    → 127.0.0.1:8080/uploads/                              │
└───────────────────────────────┬──────────────────────────────────────┘
┌───────────────────────────────▼──────────────────────────────────────┐
│                     Spring Boot 3 应用（单体，分层）                    │
│  Controller → Service → Mapper(MyBatis-Plus) → MySQL 8                │
│                                                                      │
│  横切：AuthInterceptor(JWT) → AccessInterceptor(角色/平台只读)          │
│        → AuditInterceptor(写操作/失败请求审计) → RateLimit(防重/限流)     │
│        TenantContext(ThreadLocal) → TenantLineInnerInterceptor(租户注入)│
│        CryptoService(AES 敏感字段) → GlobalExceptionHandler             │
└───────┬──────────────────────┬──────────────────────┬─────────────────┘
        │                      │                      │
   MySQL 8.0               Redis 7              本地磁盘 / MinIO
   业务与平台数据           限流/防重/编号锁/缓存    上传文件（按租户目录）
        │
   RabbitMQ（依赖已引入，异步通知为预留；当前通知落 sys_notification）
```

### 1.1 架构风格

- **模块化单体**：按业务域分包（`auth`、`booking`、`master`、`housekeeping`、`finance`、`member`、`platform`、`report`、`configcenter`），单体部署，降低民宿/中小酒店场景的运维成本。
- **前后端分离**：所有端通过统一 `/api` 访问后端，静态资源由 Nginx 托管。
- **多租户共享库共享表**：业务表含 `tenant_id`，MyBatis-Plus 租户插件自动注入过滤条件；平台表在白名单中不隔离。
- **端侧差异化**：PC 后台承载管理与一线员工操作；H5/小程序/App 承载 C 端；当前前台端、保洁端复用 PC 后台并按角色显示模块，减少重复建设。

## 3. 技术栈与选型落档

| 层级 | 选型 | 版本 | 落档说明 |
|---|---|---|---|
| 后端语言 | Java | 17 | Spring Boot 3 最低要求 |
| 后端框架 | Spring Boot | 3.2.5 | Web / Validation / Security / Data Redis / AMQP |
| ORM | MyBatis-Plus | 3.5.7 | 租户插件、分页插件、逻辑删除 |
| 数据库 | MySQL | 8.0 | utf8mb4，InnoDB |
| 缓存 | Redis | 6/7 | Lettuce 连接池 `max-active=200` |
| 消息 | RabbitMQ | 3.x | 依赖与配置已就绪；业务通知当前同步落库，MQ 为预留 |
| 鉴权 | jjwt | 0.12.x | HS256，Bearer Token |
| 后台 | Vue / Vite / TS / Element Plus | 3.5 / 5 / 5 / 2.8 | Pinia、ECharts、Axios |
| H5 | Vue / Vite / TS | 3.5 / 5 / 5 | 自定义样式，无 UI 框架依赖 |
| 小程序 | 微信原生 | 基础库 3.5 | 无第三方框架 |
| App | Flutter | Dart ≥3.3 | `http`、`shared_preferences`、`intl` |
| 对象存储 | 本地 / MinIO | MinIO 8.5.10 | 后台卡片式配置、连接测试、密钥加密 |
| 反向代理 | Nginx | 1.20+ | 静态资源 + API + 上传 |
| 进程托管 | systemd / 宝塔 | - | 生产首选；Dockerfile 仅可选辅助 |

### 3.1 关键选型理由

- **单体优先**：目标客户为单店/小型连锁，单体 + 模块化分包足以支撑，避免微服务的部署与排障成本。
- **共享库行级隔离**：租户数量可控，共享库便于平台统一统计、开通与运维；通过插件强制注入避免“漏写 where”导致越权。
- **平台/租户两级权限**：平台超管可跨租户只读下钻；租户角色按模块授权；会员仅访问本人数据。
- **多端同源 API**：H5、小程序、App 共用公开门户与会员接口，减少重复业务逻辑。

## 4. 部署拓扑

### 4.1 生产拓扑（首选）

```text
 Internet
    │ 80/443
┌───▼─────────────────────────────┐
│ Nginx（宿主机 / 宝塔）             │
│  - TLS 终止                      │
│  - portal-web/dist 静态资源       │
│  - admin-web/dist（/admin/）      │
│  - /api、/uploads 反向代理        │
└───┬─────────────────────────────┘
    │ 127.0.0.1:8080
┌───▼─────────────────────────────┐     ┌────────────────────┐
│ hotel-saas.service (systemd)     │────▶│ MySQL 8.0           │
│  Java 17 / Spring Boot           │     │ 127.0.0.1:3306      │
│  JVM -Xms512m -Xmx1024m          │     └────────────────────┘
└───┬─────────────────────────────┘     ┌────────────────────┐
    ├──────────────────────────────────▶│ Redis 7             │
    │                                   │ 127.0.0.1:6379      │
    │                                   └────────────────────┘
    └──────────────────────────────────▶ 本地磁盘 / MinIO / 外部对象存储
```

- 后端仅监听内网/回环，公网只暴露 Nginx。
- 上传目录需持久化并纳入备份；若使用 MinIO，需配置 bucket 与访问域名。
- 微信/支付/公安等外部回调统一经 Nginx → `/api/public/**` 或预留回调路径。

### 4.2 开发/验收拓扑

- `scripts/start.sh` 启动后端（默认 8080，本机演示 19090）+ Vite 开发服务器（5173/5174）。
- Vite 将 `/api` 代理到 `VITE_API_TARGET`，避免跨域。
- 小程序/真机通过局域网 IP 访问后端，需关闭开发者工具域名校验或配置合法域名。

### 4.3 Docker（可选，不构建）

仓库提供 `Dockerfile` + `nginx/nginx.conf` + `docker/supervisord.conf`，将后端、Nginx、前端产物打入单镜像。该方案仅作为辅助交付，生产仍以 Nginx + systemd 为准；本次未执行镜像构建。

## 5. 多租户与权限架构

### 5.1 租户上下文

```text
登录请求
  → AuthService 校验平台/租户/会员
  → 构造 TenantContext.User(userId, username, tenantId, tenantCode, role, platform, storeId)
  → JwtUtil 签发 JWT
后续请求
  → AuthInterceptor 解析 Bearer Token
  → TenantContext.set(user)（ThreadLocal）
  → AccessInterceptor 校验平台/租户/会员与角色模块
  → Service/Mapper 执行
  → TenantLineInnerInterceptor 自动追加 tenant_id = ?
  → afterCompletion：TenantContext.clear()
```

- 平台账号：`platform=true, tenantId=0`，租户插件对所有表跳过注入，可跨租户统计。
- 租户账号：非平台，业务表自动过滤本租户。
- 会员账号：`role=MEMBER`，仅可访问 `/api/member/**` 和公开接口，服务层再次校验本人 ID。
- 公开门户：`/api/public/{tenantCode}/**` 通过 `TenantContext.runAsTenant(...)` 临时设置租户上下文，确保租户插件生效。

### 5.2 平台表白名单

`MybatisPlusConfig.PLATFORM_TABLES`：

```text
sys_tenant, sys_platform_user, sys_dict, sys_param, sys_language, sys_menu_config
```

- `sys_menu_config` 因需按租户/端读取，加入白名单后由 `MenuController` **显式按 tenant_id 过滤**（含更新/删除/排序）。
- `sys_role`、`sys_audit_log`、`sys_tenant_dict` 等含 `tenant_id` 的表不加入白名单，由插件自动隔离。
- 平台端下钻通过请求头 `X-Tenant-Id` 临时切换租户上下文，且 `AccessInterceptor` 强制 `/api/admin/**` 仅允许 GET。

### 5.3 角色与模块授权

| 角色 | 可访问模块（`/api/admin/**`） |
|---|---|
| `TENANT_ADMIN` | 全部 |
| `STORE_MANAGER` | 除用户/审计/配置类写权限外的业务模块（当前实现按模块放行，配置类仅租户管理员） |
| `FRONT_DESK` | 订单、前台、房务、会员、主数据只读、报表、看板 |
| `HOUSEKEEPING` | 房务、主数据只读、报表、看板 |
| `FINANCE` | 财务、主数据只读、报表、看板 |
| `OTA_OPERATOR` | 订单、会员、渠道/餐饮、主数据只读、报表、看板 |
| `MEMBER` | 仅 `/api/member/**` |

> 实现位置：`AccessInterceptor`。前端 `Layout.vue` 与 `router/index.ts` 使用同一套角色路径表做菜单与路由双重过滤；后端仍是最终权威。

### 5.4 审计

- `AuditInterceptor`：对写操作、失败请求、403 响应写入 `sys_audit_log`（租户、用户、模块、动作、目标、IP、详情）。
- 订单跨租户访问在 `OrderService.mustGet` 中显式写入 403 审计。
- 平台端/租户端均提供审计查询接口；页面支持筛选展示。

## 6. 关键业务闭环

### 6.1 公开预订 → 入住 → 退房 → 房态释放

```text
C 端 H5/小程序/App
  │ 1. 查询首页/门店/房型/可用房
  ▼
GET /api/public/{tenantCode}/home|stores/{id}|room-types/{id}|availability
  │ 2. 提交预订（姓名/手机/证件/日期/房型/支付方式）
  ▼
POST /api/public/{tenantCode}/orders
  │  - 校验租户状态/日期/房量
  │  - 计算房价（房价日历优先，否则房型基准价）
  │  - 选择可用房并置 RESERVED
  │  - 生成租户内唯一订单号（Redis 锁 + 数据库唯一键）
  │  - X-Request-Id 防重
  ▼
订单 CONFIRMED
  │ 3. 前台办理入住（可换房）
  ▼
POST /api/admin/orders/{id}/checkin
  │  - 校验实名证件
  │  - 写 biz_checkin，证件 AES 加密
  │  - 写 biz_police_report（演示环境模拟成功）
  │  - 收押金写 fin_deposit
  │  - 房间置 OCCUPIED
  │  - 写订单状态日志 + 站内通知
  ▼
在住 CHECKED_IN
  │ 4. 续住 / 换房 / 补押金
  ▼
POST /extend | /change-room | /deposit
  │ 5. 退房结算
  ▼
POST /api/admin/orders/{id}/checkout
  │  - 计算房费（房价日历）
  │  - 押金抵扣、优惠、其他费用
  │  - 写 fin_settlement、fin_cashier
  │  - 退押金写 fin_deposit(REFUND)
  │  - 房间置 DIRTY
  │  - 自动创建 hk_task(CHECKOUT)
  │  - 会员积分/储值赠送
  │  - 写订单状态日志 + 站内通知
  ▼
订单 CHECKED_OUT → 保洁完成清扫 → 房间 VACANT
```

### 6.2 平台开通租户 → 租户使用

```text
平台 admin 登录（无租户编码）
  → POST /api/platform/tenants（编码/名称/类型/到期/配额）
  → 租户管理员使用租户编码 + 账号登录
  → 创建门店/房型/房间/房价
  → 配置微信/存储/菜单/语言/消息模板
  → 开展预订与接待
平台每日 01:10 TenantExpiryJob
  → 30 天内到期：写站内预警
  → 已过期：状态置 DISABLED（该租户后续登录被拒绝）
```

### 6.3 保洁闭环

```text
退房结算 → 自动生成 CHECKOUT 清扫任务（PENDING）
  → 保洁端领取/处理（PROCESSING）
  → 完成并勾选“置净”（DONE + 房间 VACANT）
  → 房态日志记录操作人/时间
异常：报修工单（REPORTED→ASSIGNED→REPAIRING→ACCEPTING→DONE）
     布草领用/送洗/归还、客诉登记与处理
```

### 6.4 报表与导出

```text
GET /api/admin/reports/summary?startDate&endDate
  → 订单、结算、房间、房型、会员聚合
  → 营收 / 间夜 / 入住率 / ADR / RevPAR / 来源 / 房型 / 门店 / 趋势
GET /api/admin/reports/export
  → UTF-8 BOM CSV（Excel 可直接打开）
```

## 7. 数据与安全设计

- **敏感字段**：身份证号、微信 AppSecret/AES Key、对象存储 AK/SK 使用 `CryptoService` AES 加密；接口返回掩码。
- **密码**：BCrypt（Spring Security `PasswordEncoder`），登录失败按 IP/账号限流。
- **JWT**：HS256，默认 12 小时；生产必须更换 `JWT_SECRET`。
- **防重**：公开下单支持 `X-Request-Id`；订单号生成使用 Redis 锁 + 唯一索引。
- **越权**：租户插件 + 服务层租户校验 + `AccessInterceptor` + 前端路由守卫四层防护。
- **上传**：按 `tenantId/category/yyyyMM/uuid.ext` 分目录；限制 20MB/文件、60MB/请求；仅允许配置的存储驱动。
- **审计**：写操作与失败访问留痕，敏感配置修改可追溯。
